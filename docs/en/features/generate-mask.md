# MindSpeed Mask Normalization

## Background and Challenges

### 1. Megatron Source Code Analysis

[1] Each device retrieves various data, including AttnMask, through `pretrain_gpt.py`-`def get_batch`.

[2] The first and last stages of PP retrieve various data, including AttnMask, through `megatron/core/utils.py`-`def get_batch_on_this_tp_rank`. Other stages directly return None.

[3] The first TP node generates the AttnMask via `megatron/core/datasets/gpt_dataset.py`-`def _get_ltor_masks_and_position_ids`.

[4] Other TP nodes directly generate an empty matrix with the same shape as the first node, and obtain the AttnMask generated by the first node through broadcast.

Tips: The above operations are enabled by default, and all generated AttnMasks are in the lower triangular shape. This can be disabled via `--no-create-attention-mask-in-dataloader`.

### 2. Problem Detection

[1] Ascend's FA requires an externally generated AttnMask, so in addition to the basic lower triangular mode, an additional interface is needed to generate custom AttnMasks.

[2] The AttnMask of non-PP head and tail nodes is `Non`e, which prevents FA acceleration from being enabled.

[3] The generation, copying, and broadcasting of AttnMask are repeated with `get_batch` at each `micro_step`.

[4] For long sequences, the generated AttnMask occupies excessive memory.

## Solution

### Solution Approach

[1] Provide a unified AttnMask generation API, where the same process reuses a global variable AttnMask to avoid repeated generation and copying.

[2] Adapt the AttnMask compression mode to reduce memory usage.

## Application Scenario

**Backend limitation:** The mask caching interface described in this document is only intended for `--transformer-impl local`.

| Configuration | Supported Scope |
| --- | --- |
| `--attention-mask-type causal` | Default value, causal attention; supports Ring, Ulysses, KVAllGather, and hybrid CP. |
| `--attention-mask-type general` | General training supports Ring, Ulysses, and hybrid CP. EOD Reset is available only when CP=1. |
| `--use-flash-attn --sparse-mode 0` | Default mode, computed based on the passed-in mask. |
| `--use-flash-attn --sparse-mode 2` | A causal compressed mask aligned to the upper left. |

When CP>1, `--transformer-impl transformer_engine` is required. When combined with EOD Reset, only `p2p/all_gather + causal` is supported. For specific constraints, see [EOD Reset](eod-reset.md). `attention-mask-type` and `sparse-mode` are different parameters, and the operator mode used internally by TENPU is not equivalent to the selectable range of the startup parameters.

The local DotProductAttention path generates and caches the mask when the mode is causal and the passed-in mask is None; FA generates a compressed mask of [2048,2048] by default, and the `multi_head_latent_attention` configuration uses the full sequence length. Non-FA uses the full mask.

## Usage

[1] To address the above issues and ideas, AttnMask is directly enabled by default in MindSpeed, and the native mask generation method is no longer used.

[2] A global variable `_GLOBAL_ATTN_MASK` is provided in `mindspeed/core/transformer/flash_attention/generate_mask/generate_mask.py`.

[3] The `--sparse-mode` parameter is provided to work with multiple FA modes. For information on the different modes of `--sparse-mode`, refer to the [torch_npu.npu_fusion_attention operator documentation](https://www.hiascend.com/document/detail/en/Pytorch/60RC2/apiref/apilist/ptaoplist_001095.html).

[4] Three additional APIs `set_attention_mask`, `get_attention_mask`, and `generate_attention_mask` are provided in `mindspeed/core/transformer/flash_attention/generate_mask/generate_mask.py` to implement setting, getting, and generation functions outside the normal flow.

[5] The local DotProductAttention generates the mask when it is first needed through `dot_product_attention_forward_wrapper` in `mindspeed/core/transformer/flash_attention/generate_mask/adaptor.py`; CP attention is handled by TENPU.

## Effects

For example, in the lower triangular mode, setting sparse_mode=2 in compressed mode fixes the mask.shape to [2048, 2048], which significantly improves performance and reduces memory usage.

## Notes

The automatically generated FA mask is a causal mask; setting `general` does not automatically generate an arbitrary custom mask. `set_attention_mask` is only used to set the local cache and does not change the support restrictions of CP/EOD or `--sparse-mode`.
